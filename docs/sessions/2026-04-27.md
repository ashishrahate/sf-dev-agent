## What was delivered

### Schema migration (`context/schema.sql`)
Added the `memories` table alongside `components` and `knowledge_entries`. Same SQLite file (`default_db_path()`), same embedding shape (BLOB + content hash). Multi-tenant from day one (`tenant_id`, `org_alias`) even though runtime is single-tenant. `superseded_by` self-FK with `ON DELETE SET NULL` for the future compaction story (slice 2).

```sql
memories(id, tenant_id, org_alias, type, name, description, body,
         tags_json, source_session_id, created_at, last_accessed_at,
         access_count, superseded_by, embedding, embedded_text_hash)
```

Indexes: `(tenant_id, org_alias)`, `type`, `superseded_by`.

### `MemoryStore` (`memory/store.py`)
Mirrors the `KnowledgeBase` shape — same SQLite + numpy cosine + hash-gated embed pattern, deliberately so a future swap to pgvector is one class refactor in three places, not three. Public API:

- `save(scope, type, name, description, body, tags?, source_session_id?, memory_id?)`
- `recall(query_embedding, scope, type=None, limit=10, include_superseded=False)`
- `list(scope, type=None, include_superseded=False, limit=50)`
- `find_by_id`, `supersede`, `delete`, `embed_pending`, `stats`, `embedding_stats`

Save validates against `MEMORY_TYPES` (locked taxonomy), rejects blank required fields, and **drops the embedding when body changes** so the next `embed_pending()` rebuilds the stale vector. Recall **bumps `last_accessed_at` and `access_count`** on every returned row — feeds the decay scoring planned for slice 2.

The scope filter does what the design called for: tenant strict equality, org_alias matches the requested org OR `NULL` (cross-org-within-tenant rows). A NULL row is the "user prefs apply to every org" lane.

### Three tools wired (`tools/registry.py`)

| Tool | Read-only? | Mock-mode? |
|---|---|---|
| `memory_save` | No (writes; needs plan approval) | Pure local SQLite — runs normally |
| `memory_recall` | Yes | Yes (Gemini call to embed query) |
| `memory_list` | Yes | Pure local SQLite — runs normally |

`_memory_scope()` helper builds the scope from `OrgConnection.tenant_id` + `org_alias`. `cross_org=True` on `memory_save` drops the org pin so a row applies tenant-wide.

The `retrieve_context` tool schema gained a `memory_type` filter; the orchestrator's call always passes the current org's `memory_scope` so the agent never has to think about scoping by hand.

### Orchestrator integration (`context/orchestrator.py`)
Added `_layer_memory` adapter (mirrors `_layer_knowledge`). The 4-source fan-out is layered, not stacked: memory hits compete on cosine score with semantic + literal + knowledge in the same dedupe + budget pipeline. Memory hits have `component_id=None` so they pass through `_dedupe_by_component` unchanged (same as knowledge hits).

Layer is **opt-in via `memory_scope`** — None disables it for one-shot/utility calls. The registry passes the current org's scope by default.

### System prompt (`prompts/system_prompt.md`)
Replaced the placeholder `### memory_recall` section with full `memory_save` + `memory_recall` + `memory_list` documentation. Ported from Claude Code's auto-memory system prompt:

- The four-type taxonomy with one-line definitions.
- Save triggers — corrections AND validated non-obvious choices (the easy-to-miss case).
- Body convention — `**Why:**` / `**How to apply:**` so future-you can judge edge cases.
- Verify-before-use rule — a memory is a *claim*; re-grep before acting on it.
- What NOT to save — patterns, file paths, git history, ephemeral context.

### Mock-mode (`tools/mock_responses.py`)
Added a canned response for `memory_recall` (returns `match_count=0`, `mocked=True`). Updated the `retrieve_context` mock to include `memory: 0` in its `layer_counts` dict.
