## What was delivered

### C.3 — ESC / Ctrl+C interrupt (`8974276`)

**`src/sf_dev_agent/interrupt.py` (new)**: `InterruptListener` context manager runs a daemon thread polling stdin for ESC. Cross-platform via `msvcrt.kbhit() / getch()` on Windows and `tty.setcbreak() + select.select()` on POSIX. Non-TTY environments (tests, piped input, CI) are a no-op — the listener is still usable as a passive flag holder so callers can check `is_set()` uniformly without branching.

**`agent.py` integration**: `_agent_loop` wraps iterations in the listener context. The streaming `on_text` callback polls `interrupt.is_set()` and raises `InterruptedError` to abort the stream cleanly. Both `InterruptedError` and `KeyboardInterrupt` are caught at the same level — same handler for ESC and Ctrl+C. A second poll-point sits between the LLM stream and tool dispatch so an interrupt during the model's response cancels the tools it tried to emit. After interrupt, a synthetic `<user pressed ESC>` user message lands in the conversation transcript so the next turn has the partial output as context.

**Design choice — poll-based, not signal-based.** Background thread sets a `threading.Event`; the on_text callback polls and raises. SIGINT delivery is patchy on Windows, and signal handlers can't run from arbitrary threads anyway. Polling sidesteps both issues and the listener's no-TTY no-op makes it safe in CI.

**`tests/test_interrupt.py`**: 7 tests. Listener mechanics (no-op when stdin not TTY, fire/reset, thread cleanup on `__exit__`); agent integration (mid-stream `InterruptedError` aborts and records sentinel; mid-stream `KeyboardInterrupt` handled identically; post-stream interrupt skips tool dispatch).

### C.4 — Resume-by-LLM-intent via 3 tools (`1c21092`)

**Three tools in `tools/registry.py`:**

- **`list_resumable_tasks`** (read-only) — browses `WorkingMemoryStore.list_tasks` filtered to non-terminal statuses (planning / awaiting_approval / executing); optional `include_terminal` for history view. Scoped to current (tenant, org) automatically.
- **`get_task_summary`** (read-only) — returns one task's status, plan, error, and a transcript head with content blocks compressed to short snippets (text → first 200 chars; tool_use → `[tool_use <name>]`; tool_result → `[tool_result]`). Cross-tenant requests are refused.
- **`request_resume`** (intercepted) — exposed to the LLM with a schema; never reaches the registry executor. Intercepted in `AgentLoop._execute_tool` the same way `submit_plan` is.

**Intercept handler** (`agent.py`): stamps `agent.resume_requested = task_id`, returns a synthetic `tool_result` with `{resume_signaled: True, task_id, next: "..."}` so the model sees a clean confirmation (not an error). Defensively rejects unknown task_ids and cross-tenant ids before setting the flag — bad input returns an `is_error` tool_result and leaves `resume_requested = None`.

**Loop exit** (`agent.py`): after the tool_result block lands in the transcript, if `resume_requested is not None`, the loop breaks. The synthetic confirmation message persists on disk so the resumed task picks up cleanly.

**REPL hand-off** (`repl.py`): `_dispatch_agent` reads `agent.resume_requested` after `run()` returns. If set, it calls `AgentLoop.resume(task_id, ...)` so the user lands back in the resumed task in one keystroke. Wrapped in a `while` loop so a chain of resumes is technically supported (rare, but cheap).

**ToolRegistry signature change**: now accepts an optional `WorkingMemoryStore` handle so the read-only tools have access without a second SQLite open. `AgentLoop.__init__` passes `working_memory` through.

**Design choice — intercepted tool, not regex classifier.** The LLM does its own intent recognition. Phrases like "resume what I was doing", "let's pick up where we left off", "continue my deploy task" all work without enumeration. Why intercept rather than use a normal tool: resume requires *replacing* the current `AgentLoop`, which an in-loop tool executor can't do.

**`tests/test_resume_by_intent.py`**: 10 tests covering tool shapes (in-flight only by default, include_terminal, no-WM error), `get_task_summary` head/cross-tenant guard, intercept behavior (sets `resume_requested`, persists confirmation), defensive guards (unknown task / cross-tenant), and REPL hand-off (verifies `AgentLoop.resume` is called once with the right task_id).

### C.5 — Extract nudge at /quit (`b06240e`)

**`src/sf_dev_agent/extract_nudge.py` (new)**: `prompt_extract_if_needed(session)` runs at end-of-REPL when `session.completed_task_ids` is non-empty. Soft prompt `[yes / skip / no-and-stop-asking]`. Yes walks each transcript through `MemoryExtractor`, presents candidates inline (yes/no/edit per candidate), and writes accepted candidates to `MemoryStore` under the current (tenant, org) scope.

**Skip-sentinel**: per-(tenant, org) file at `<cache>/.skip_extract_<tenant>_<org>` — same shape and pattern as the B.2 warmup nudge for UX consistency. Filename is sanitized (alphanumeric + `-_.` only) so org aliases with slashes/colons don't break the path.

**`launch_repl` integration** (`repl.py`): at the end of the prompt loop, before the final "Session ended" line, the nudge is invoked. Wrapped in try/except so a nudge crash doesn't break the teardown — the user always sees "Session ended" cleanly.

**Design choice — end-of-session, not per-task.** Single soft prompt at `/quit` keeps approval fatigue low. The earlier "per-task extract nudge" idea was dropped in the C.5 design. One-shot CLI runs don't get the nudge — they don't go through `launch_repl`.

**`tests/test_extract_nudge.py`**: 10 tests covering sentinel round-trip, sanitization of org aliases, no-completed-tasks short-circuit, no-working-memory short-circuit, sentinel-already-set short-circuit (asserts `Prompt.ask` is never reached), all three answer paths, and the yes-path persisting accepted candidates under the right scope. The yes-path test uses an alternating `["yes", "yes", "no"]` answer iterator to simulate "open soft prompt → accept candidate 1 → reject candidate 2".

## Architectural choices locked in Phase C

- **Streaming abstraction is provider-agnostic.** `StreamChunk` + `consume_stream` decouple real streaming from pseudo-streaming. Adding real streaming for Anthropic / OpenAI is opt-in (override `chat_stream`) and doesn't break anything.
- **Interrupt is poll-based.** See C.3 above — sidesteps Windows SIGINT issues and works cleanly in non-TTY environments.
- **Resume is intercepted at the tool-call boundary**, not the LLM-input boundary. Lets the LLM do intent recognition; the REPL handles the loop swap.
- **Extract nudge is end-of-session.** Single prompt at `/quit`, not per-task. Per-(tenant, org) skip sentinel parallels the B.2 warmup pattern.
- **REPL dispatcher is split from `prompt_toolkit`.** All routing logic is testable without touching the interactive layer.
